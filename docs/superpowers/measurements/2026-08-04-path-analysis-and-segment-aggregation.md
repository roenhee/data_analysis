# 측정: 경로 분석 15일 실측과 세그먼트 집계 결함

**날짜:** 2026-08-04 · **대상:** 2026-07-14~28 15일, 6서비스, 사전 `sd_2ab5ec25e750dda2`
**계획서:** `plans/2026-07-30-action-layer-analyses-handoff.md` (통과 후 할 일)
**결론:** 세 가지다. ① `path` 큐브 15일(**1,929만 행**) 로딩은 **0.5초**로 병목이 아니다 —
대시보드 설계를 바꿀 이유가 없다. ② `path_ranking`·`markov_order_test` 는 **세그먼트(축
조합)별로 쪼개진 큐브를 합치지 않아 둘 다 틀린 값을 냈다.** `markov` 는
`excess_information` 이 **-6.29 nats**(KL 은 음수가 불가능)였고 `path_ranking` 은 고유 경로가
아니라 조각을 순위 매겼다. 이 커밋에서 고쳤다. ③ 고친 뒤 판정: **1차 마르코프 가정은
실측에서 약하다** — `excess_information` **0.504 nats** 로, 직전 화면을 하나 더 알면 다음
화면 예측이 유의하게 나아진다.

## 왜 재야 했나

인수인계 문서가 두 가지를 "반드시 측정" 으로 남겼다. `path` 15일 로딩 시간(2,040만 행을
pandas 에 통째로 올리는 구조라 대시보드 설계가 여기 걸릴 수 있었다)과 `excess_information`
실측값(**아무도 본 적이 없고**, 이 프로젝트의 마르코프 분석 전체 — `screen_flow`·
`screen_pair_affinity` — 가 기대는 1차 가정이 실제로 성립하는지를 판정한다).

측정하자마자 이 프로젝트의 지배적 실패 모드가 그대로 나왔다: **그럴듯한데 틀린 숫자.**
단위 테스트 821개가 통과했고 예외도 안 났지만 실데이터 값은 불가능한 음수였다.

## ① `path` 큐브 15일 로딩은 병목이 아니다

로컬 캐시 parquet 을 pandas 로 읽은 시간(Trino 미접속):

| 큐브 | 15일 행 수 | 로딩 | 비고 |
|---|---|---|---|
| session | 214,668 | 0.1s | |
| transition | 3,279,905 | 0.1s | |
| quality | 251,822 | 0.0s | |
| **path** | **19,291,345** | **0.5s** | 디스크 223 MB · **pandas 메모리 약 4.0 GB** |
| action | 9,291,391 | 0.2s | |
| cond_transition | 352,657 | 0.0s | |
| **6큐브 합** | | **0.9s** | |

로딩은 문제가 아니다. **메모리는 다르다** — `path` 를 통째로 올리면 약 4 GB 다(문자열 경로가
행마다 반복된다). 세그먼트를 먼저 좁혀 부르라는 경고의 근거는 시간이 아니라 이 메모리다.

## ② 세그먼트 집계 결함 — 두 분석이 조각 단위로 계산했다

`path` 큐브는 `(service_type, os, gender, age_band, daypart, app_version, period, n)` 조합마다
상위 200 경로를 남기고 나머지를 그 조합의 `(other)` 로 접는다(`cube/sql.py` 의
`PARTITION BY {axis_names}, n`). **전체 rollup 행이 없다.** 그래서 같은 경로가 하루에도
평균 **196개 조각 행**으로 존재한다(최다 `top/엠탑조회>top/엠탑조회>top/엠탑조회` 가 2,971개).

두 분석이 이 조각을 키로 합치지 않았다. 전이 큐브를 쓰는 분석들은 `transition_matrix()` 나
명시적 `groupby().sum()` 으로 세그먼트를 먼저 접는데, 경로 분석만 빠졌다.

| 값 | 결함 상태 | 수정 후 | 원인 |
|---|---|---|---|
| `markov` `excess_information` | **-6.292872** | **0.504083** | 관측은 조각(합 안 함), 1차 예측은 `groupby.sum()`(합함) → 스케일 불일치로 조각 확률이 예측보다 작아 KL 음수 |
| `path_ranking` n=3 `paths` | 5,611,080 | **2,352** | 고유 경로가 아니라 세그먼트×경로 조각 수 |
| n=3 `top_path_share` | 0.0009 | **0.0638** | 최빈 경로의 비중이 아니라 조각 하나의 비중 |

`coverage` 는 결함이 없었다 — `1 - (other)합/전체합` 이라 세그먼트 집계와 무관하다(그래서
아래 ③ 의 커버리지는 수정 전에도 옳았다).

**단위 테스트가 왜 못 잡았나:** 픽스처는 경로마다 단일 행(단일 세그먼트)이라 집계 여부가
결과를 바꾸지 않는다. 실데이터는 경로당 평균 196조각이라 발현한다. 재현 테스트 3개를
추가했고(세그먼트 조각 픽스처), mutation 5종을 되주입해 전부 잡히는 것을 확인했다.

## ③ `path_ranking` 실측 (수정 후)

| n | coverage | 고유 경로 | `top_path_share` | `distinct_dropped` |
|---|---|---|---|---|
| 3 | 0.9860 | 2,352 | 6.38% | 2,683,448 |
| 4 | 0.9013 | 13,475 | 5.91% | 13,698,651 |
| 5 | 0.7740 | 45,838 | 5.58% | 35,241,123 |

경로가 극도로 분산돼 있다 — 최빈 3-gram 조차 6.4% 다. n 이 커질수록 `(other)` 가 커져(n=5
는 22.6%) `path_tail_dominates` 에 가까워진다. `distinct_dropped` 는 **세그먼트별 잘린 고유
경로 수의 합**이라 세그먼트 간 중복을 포함한 상한이다(전체 고유 잘린 수의 정확값은 큐브만
으로는 알 수 없다).

## ④ `markov_order_test` 실측 — 1차 마르코프 판정

| | 값 |
|---|---|
| `excess_information` | **0.504083 nats** |
| `contexts` (검정된 3-gram 문맥 수) | 207 |
| `coverage` (상위 200 컷 이후 검정 범위) | 0.9860 |
| `diverging_context_share` (KL>0.1 문맥의 물량 비중) | **0.9812** |

**판정: 1차 가정은 약하다.** `excess_information` 0.504 nats 는 `screen_pair_affinity` 의
상호정보량 I(현재;다음)=**0.641 nats** 에 견줄 만한 크기다 — 직전 화면 하나가 현재 화면이
주는 정보의 약 79% 에 맞먹는 예측 개선을 더한다. 물량의 **98.1%** 가 발산 임계 0.1 을 넘는다.

즉 `screen_flow`·`screen_pair_affinity` 처럼 "다음 화면은 현재 화면만으로 정해진다" 를
가정하는 지표는 **무시할 수 없는 모형 오차를 담고 있다.** 물량 상위 문맥의 발산은 0.17~0.46
(예: `top/엠탑조회`→`media/m_newsview_보기` 0.465). 발산 자체가 가장 큰 것은 관측 6~48건짜리
`content_v/other`·`top/다음_PC탑` 문맥으로, 얇은 셀이 크게 튀는 것은 예상된 거동이다.

## 결정

**① 경로 큐브를 쓰는 분석은 세그먼트를 키로 먼저 합친다.** `metrics/paths.py` 가
`groupby("path")`(순위)·`groupby(["prev_state","state","next_state"])`(3-gram) 로 접는다.
rollup 행이 없는 큐브에서 이걸 빠뜨리면 예외 없이 조각을 센다.

**② 1차 모형 분석의 해석에 모형 오차를 명시한다.** `screen_flow` 의 기대 걸음 수·이탈확률은
1차 근사값이고, 실측 `excess_information` 0.504 nats 만큼 직전 화면 정보를 버린다. 세그먼트
비교에서 부호가 뒤집히는 정도의 미세한 차이는 이 오차 안에 있을 수 있다.

**③ `path` 큐브는 세그먼트를 먼저 좁혀 부른다.** 15일 전체는 pandas 메모리 약 4 GB다.
`load_cube_set(..., cube_names=ALL_CUBE_NAMES)` 로 부르되 필요한 축으로 `filter` 를 건다.

## 아직 재지 않은 것

**세그먼트별 컷이 상위 경로 cnt 를 과소평가하는 정도.** 어떤 경로가 세그먼트 A 에선 상위
200 에 들고 B 에선 `(other)` 로 잘리면, 합산 cnt 는 A 조각만 잡고 B 조각은 `(other)` 에
숨는다. n=3 은 `coverage` 0.986 이라 영향이 미미하지만 n=5(0.774)에서는 상위 경로 순위가
이 누수로 흔들릴 수 있다. `path_tail_dominates` 경고가 그 경계를 가리키지만 왜곡의 크기는
아직 재지 않았다 — 재려면 컷 없는 원천 3-gram 을 세그먼트 무관하게 다시 집계해야 한다.
