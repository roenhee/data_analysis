# 대시보드 UX 개편 설계 (2026-08-05)

**한 줄**: 단일 모드 대시보드를 **B형 레이아웃(상단 컨트롤바)** + **Vega-Lite 시각화** +
**페이지네이션**으로 재구성한다. 분석별 세부 튜닝과 비교 모드는 이 골격 위에서 이어간다.

## 배경 — 왜 손보나

4단계 대시보드(`specs/2026-08-04-dashboard-design.md`)는 단일 모드 골격을 세웠지만 두 가지가 약하다.

- **시각화가 Streamlit 기본 차트에 묶여 있다** — `st.bar_chart`·`st.line_chart`·표+그라데이션이라
  축·색·툴팁·정렬을 제어할 수 없고, 히트맵도 진짜 히트맵이 아니라 표에 색만 입힌 것이다.
- **컨트롤이 사이드바에 세로로 몰려 있다** — 기간·서비스·세그먼트 축 6개·분석·파라미터·공유가
  전부 좌측에 쌓여 화면을 한눈에 훑기 어렵다.

2026-08-05 브레인스토밍에서 전체 UX를 손보기로 했다. 시각화 기술은 **Vega-Lite(Altair)** 로 정했다
— D3를 선언적으로 감싼 문법이라 표현력을 얻으면서 Streamlit 네이티브(`st.altair_chart`)라
통합 비용이 없다. 군집 네트워크처럼 D3가 확실히 나은 특수 뷰는 나중에 국소 투입 여지를 남긴다.

## 작업 분해 (이 순서로 진행)

| # | 작업 | 이 스펙에서 |
|---|------|---------|
| **1** | **공통 골격 재구성** (B형 + Vega-Lite + 페이지네이션) | ★ **이 문서** |

| 3 | 비교 모드 (`compare_view`) | 2026-08-04 문서 "비교 모드"의 실현 (별도 스펙) |

이 문서는 **1단계만** 다룬다. 2·3단계는 골격이 선 뒤 각자 스펙으로 이어간다.

## 1단계 — 공통 골격 스펙

### 레이아웃: B형 (상단 컨트롤바)

```
┌──────────────────────────────────────────────────────┐
│ [ 단일 │ 비교 ]   기간  서비스  앱버전 OS 성별 연령 …   │ ← 상단 컨트롤바
├──────────────────────────────────────────────────────┤
│ 개요 · 화면흐름 · 행동 · 서비스 · 품질                    │ ← 분석 탭
├────────────┬─────────────────────────────────────────┤
│ 분석 ▾      │ 지표카드 행                               │
│ 파라미터    │ Vega-Lite 차트 (상위 N)                   │
│ (얇은 사이드)│ 표 (페이지네이션)                         │
│            │ ⚠ 봉투                                    │
└────────────┴─────────────────────────────────────────┘
```

- **최상위 `[단일 | 비교]` 토글**을 상단 컨트롤바 왼쪽에 둔다. 비교는 3단계에서 활성화하므로,
  1단계에서는 **단일 고정**(비교는 비활성/"준비 중" 표시)으로 자리만 잡는다.
- **세그먼트(기간·서비스·축 6개)를 상단 컨트롤바로 이동**한다. 사이드바에서 빠져나온다.
- **사이드바는 분석 selectbox + 파라미터만** 남아 얇아진다.
- **메인이 넓어진다** — 지표카드 행 → 차트 → 표 → 봉투.

### 시각화: Vega-Lite 전환

- `charts.py` 를 **Vega-Lite(Altair) 스펙 생성**으로 재작성한다. `viz.kind`(bar/line/heatmap)를
  읽어 Altair 차트 객체를 반환하는 순수 함수로. `st.*` 호출은 여전히 `app.py` 만.
- **heatmap 을 진짜 히트맵으로** — 현재 표+`background_gradient` 를 Altair `mark_rect` 격자로.
- **색맹 친화 팔레트 유지**(Tableau 10, 현재 `_PALETTE`).
- **군집 그래프(`viz.kind == "graph"`)는 현행 graphviz 유지** — Vega-Lite 전환 범위 밖.
  (D3 force 레이아웃 국소 투입은 나중 옵션.)
- `app.py` 의 `st.bar_chart`/`st.line_chart`/`st.dataframe`(heatmap 분기)을 `st.altair_chart` 로 교체.

### 표시 개수 → 페이지네이션

- **표시 개수 `number_input` 위젯 제거.** (사이드바가 더 가벼워진다.)
- **표: 전체를 페이지네이션**으로 — 페이지당 고정 행수, 페이지 이동 컨트롤. 전 행을 다 볼 수 있다.
- **차트: 상위 N개 고정 렌더** — `path_ranking`(고유 경로 수천~수만)처럼 큰 프레임에서 막대 수천 개는
  무의미하므로 상위만 그린다. N값과 화면별 예외는 **2단계 튜닝**에서 정한다(1단계는 기본값).
- **headline 카드·봉투는 개수와 무관하게 전량 표시.**

### 16개 분석 렌더 유지

- 기존 **16개 분석**(session_trend·screen_flow·screen_dwell_rank·screen_pair_affinity·
  screen_transition·hub_neighbors·reachability·screen_communities·community_paths·
  click_distribution·conditional_flow·path_ranking·markov_order_test·cross_service_flow·
  quality_report)이 새 골격·Vega-Lite에서 **회귀 없이 다 렌더**되는 것이 1단계 종료 조건.
- 화면별 카드·차트·표 구성 최적화는 **2단계**에서 실물 보며 하나씩.

## 파일별 변경

| 파일 | 변경 |
|---|---|
| `dashboard/app.py` | 레이아웃 재배치(세그먼트를 상단 컨트롤바로), 표시개수 위젯 제거, `st.altair_chart` 호출, 페이지네이션 컨트롤, `[단일\|비교]` 자리(단일 고정) |
| `dashboard/charts.py` | `viz.kind` → **Altair 차트 객체** 생성으로 재작성. heatmap 은 `mark_rect` |
| `dashboard/render.py` | `table_slice` → **페이지네이션 헬퍼**(페이지 → 행 슬라이스) |
| `dashboard/state.py` | `top` 제거, **`page` 상태** 추가(URL 왕복 유지) |
| `dashboard/layout.py` (신규, 필요시) | 상단 컨트롤바 위젯 묶음. `app.py` 가 커지면 분리 |

각 파일 단일 책임 유지. 숫자는 전부 `analyses/` 호출, 대시보드에 계산 로직 없음(기존 경계 그대로).

## 테스트 전략

- **`charts.py`** — `viz.kind` 별로 올바른 Altair 스펙(mark·encoding)이 나오는지 순수 함수 테스트.
- **`render.py`** — 페이지네이션 슬라이스가 페이지·행수대로 잘리는지(경계: 마지막 페이지·빈 프레임).
- **`state.py`** — URL 왕복에 `page` 반영, `top` 제거 후에도 기존 상태 왕복 항등.
- **`app.py`** — 위젯 배치·상호작용은 자동 테스트가 어려워 **브라우저 수동 스모크**(preview).
- **분석 숫자 정확성**은 기존 `test_analyses_on_real_cubes.py` 등이 이미 지킨다(대시보드는 호출만).

## 범위 밖 (이 스펙에서 안 함)

- **분석별 세부 튜닝** — 2단계. 카드 개수·차트 종류 미세조정·화면별 상위 N 등.
- **비교 모드** — 3단계. `compare_view`, A/B 대조 뷰(연산자는 이미 있음).
- **군집 그래프 D3 전환** — 필요성 확인 후 별도.
- **새 분석 추가·큐브 변경** — agorax 재빌드는 4단계 별도 백그라운드 작업.

## 열린 질문 (구현 계획에서 확정)

- **Altair 설치 여부** — Streamlit 의존에 포함되나 확인 필요(`st.altair_chart` 는 있음).
- **페이지네이션 방식** — Streamlit 네이티브 위젯(`st.dataframe` 자체 스크롤) vs 명시적 페이지 컨트롤.
  실물에서 어느 쪽이 나은지 스모크로 정한다.
- **상단 컨트롤바 위젯 밀도** — 축 6개가 한 줄에 다 들어갈지, `st.columns`/`st.popover` 로 접을지.
