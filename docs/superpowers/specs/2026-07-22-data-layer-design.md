# 데이터 접근·캐시 레이어 설계 (Data Access & Cache Layer)

- 날짜: 2026-07-22
- 상태: 설계 확정 (구현 계획 대기)
- 범위: 정량 분석 플랫폼의 **서브프로젝트 ①** — 공통 데이터 기반 레이어

## 배경

회사 로그 데이터를 Trino(`hadoop-rabbit-trino.onkakao.net`, catalog `hadoop_rabbit_iceberg`, schema `axz_da`)로 조회해 markov 등 정량 분석을 수행한다. 기존 markov 워크플로(`리서치/markov`)의 문제:

- 원본이 약 9.4억 행. 세션 기준 ~100만 행을 샘플링해 서버에 `_rowdata` 테이블을 만들고, 상태매핑·전이·markov 계산을 전부 서버 쿼리(CREATE TABLE 연쇄)로 수행한다.
- 그 결과 (1) 매번 느리고, (2) 서버에 중간 테이블이 계속 쌓이며, (3) 노트북 수동 실행이라 재현이 어렵다.

이 레이어는 그 세 가지를 없애는 공통 기반이다. 분석 스킬(서브프로젝트 ②)과 플랫폼(서브프로젝트 ③)이 모두 이 레이어 위에 올라간다.

## 전체 시스템에서의 위치 (참고)

전체 플랫폼은 3개 서브프로젝트로 분해했고, 본 문서는 ①만 다룬다.

- **① 데이터 접근·캐시 레이어** (본 문서) — 공통 기반.
- **② 분석 스킬들** (Claude Code) — 해석이 필요한 정량 분석. 이 레이어를 import해서 사용.
- **③ 플랫폼** (웹, 혼자 쓰되 읽기전용 웹 공유) — 기록·시각화·대시보드·스킬 프롬프트 카탈로그. 스킬 결과물 파일과 매니페스트를 읽어 표시.

스킬↔플랫폼은 자동 파이프라인이 아니라 **사람이 직접** 오간다: CC에서 스킬을 돌려 결과 파일을 만들고, 플랫폼이 그 파일과 매니페스트를 읽는다.

## 핵심 결정 사항

1. **형태**: 공용 파이썬 패키지 `data_layer/`. 각 분석 스킬이 `import`해서 사용한다. (별도 조회 스킬/CLI 아님 — 호출 단계를 늘리지 않기 위해)
2. **연산 위치 (하이브리드, "서버가 줄이고 로컬이 캐시한다")**: 무거운 집계/축소는 Trino에서 하되 결과는 작게 만들어 로컬로 가져오고, 이후 분석 연산은 로컬 DuckDB에서 수행한다.
3. **서버 잔여물 0**: 서버 임시 테이블은 세션 프리픽스로 만들고, 결과를 pull한 직후 DROP한다. 누락 대비 sweep 정리 기능을 둔다. 서버에 아무것도 영구히 남기지 않는다.
4. **캐시 무효화**: 내용 기반 + 수동 갱신. 캐시 키 = `hash(쿼리문 + 기간/파라미터)`. 같은 요청이면 영구 재사용, `refresh=True`일 때만 재조회.
5. **2층 캐시**:
   - **기반 데이터셋**(원본 샘플 이벤트 행)은 **일자별 조각**으로 캐시 → 범위 재사용·델타 fetch·보유기간 표시가 자연스럽게 나온다. 상태 정의(state)는 분석마다 바뀔 수 있는 분석 관심사이므로 캐시에 굽지 않는다. 상태 매핑은 로컬에서 수행하는 첫 분석 단계로 둔다(그래야 상태 정의가 바뀌어도 기반 캐시가 무효화되지 않는다).
   - **파생 집계 결과**는 **내용 해시**로 캐시(날짜로 쪼개 재사용 불가한 비율/집계 대상).
6. **매니페스트**: 캐시가 무엇을 갖고 있는지의 색인. 스킬(재사용 판단)과 플랫폼(보유 기간 표시)이 공용으로 읽는다.
7. **표본 크기는 실측으로 결정**: 표본을 키우며 핵심 지표가 안정되는지 확인하는 수렴 체크를 제공한다. "많을수록 정확"의 이득은 √n으로만 커지고 편향은 줄지 않으므로, 양은 철학이 아니라 데이터가 정하게 한다.

## 데이터 흐름

```
Trino (전수 ~9.4억행, 집계/축소만)
  └─ 서버 임시 테이블 (세션 프리픽스) ──(결과 pull)──▶ 로컬 parquet 캐시 ──▶ DuckDB 로컬 연산
        └─ pull 직후 즉시 DROP (finally에서 보장, sweep으로 이중 안전)
```

- 첫 실행: 서버에서 필요한 만큼 축소 → 로컬 조각 저장 → 서버 테이블 DROP.
- 재실행: 매니페스트 확인 → 이미 있는 날짜/결과는 네트워크 0으로 재사용, 빠진 부분만 fetch.
- 모든 다운스트림 분석(상태매핑·전이·markov 등)은 로컬 parquet 위 DuckDB에서 수행 → 빠르고 오프라인·재현 가능.

## 로컬 캐시 레이아웃

```
cache/
  events/                        # 기반 데이터셋: 원본 샘플 이벤트 행 (일자별 조각)
    day=2025-01-05.parquet
    day=2025-01-06.parquet
    ...
  results/                       # 파생 집계 결과 (내용 해시)
    <hash>.parquet
    ...
  manifest.json                  # 색인: 스킬 + 플랫폼 공용
```

- 요청 기간 = 해당 기간의 날짜 조각 합집합. 있는 날은 재사용, 빠진 날만 서버에서 가져와 조각 추가.
  - 예: `2025-01-05~02-01` 보유 상태에서 `~02-02` 요청 → **02-02 하루만** fetch.
- 일자별 델타 재사용은 **행 단위 기반 데이터에만** 적용된다. 비율/집계 같은 파생 결과는 날짜로 분해되지 않으므로 내용 해시 캐시로 다룬다(재계산은 로컬 이벤트 캐시에서 빠르게).

## 매니페스트 (`cache/manifest.json`)

캐시 색인. 최소 스키마:

- `events`: 조각별 `{ day, rows, size_bytes, source_query_hash, created_at }`
- `results`: 항목별 `{ hash, source_summary, date_range, params, rows, size_bytes, created_at }`

`manifest.py`가 읽기/쓰기와 질의 API를 제공하고, 플랫폼(③)이 이 API를 그대로 사용해 "보유 기간"과 "캐시된 결과 목록"을 표시한다.

## 패키지 구성 `data_layer/`

각 모듈은 하나의 책임만 갖고 잘 정의된 인터페이스로 통신한다.

- `connection.py` — Trino 커넥션. context manager로 열고 닫는다. 접속 정보는 `config`에서 주입받는다.
- `fetch.py` — `get_events(start, end, refresh=False) -> DataFrame`. 매니페스트로 보유 날짜 확인 → 빠진 날만 서버 조회 → 원본 샘플 행 조각 저장 + 매니페스트 갱신 → 서버 임시 테이블 DROP → 요청 기간을 합쳐 반환. (상태 매핑은 이 결과 위에서 분석 스킬이 로컬로 수행)
- `query.py` — `run(sql, params=None, refresh=False, target="local") -> DataFrame`. 기본은 로컬 DuckDB(캐시된 parquet 대상), 결과를 해시로 캐시. `target="server"`면 무거운 축소를 Trino에서 수행 후 결과만 로컬 캐시.
- `manifest.py` — 매니페스트 읽기/쓰기 + 질의 API(보유 기간, 캐시 목록). 스킬·플랫폼 공용.
- `cleanup.py` — 세션 프리픽스 기준 서버 임시 테이블 일괄 정리(sweep). 정상 경로의 즉시 DROP이 누락됐을 때의 안전망.
- `convergence.py` — `check_convergence(analysis_fn, sizes=[1e6, 5e6, 2e7]) -> report`. 표본 크기를 키우며 핵심 지표가 안정되는지 리포트해, 필요한 표본 크기를 실측으로 정하게 한다.
- `config.py` — 접속 정보·캐시 디렉터리 경로 등 설정. (인증정보 처리는 아래.)

## 인증정보 처리

기존 `리서치/markov/env.py`는 TIARA ID/PW를 평문으로 담고 있다. 이 레이어에서는:

- 접속 정보를 환경변수(또는 gitignore된 로컬 설정 파일)에서 읽는다.
- 자격 증명을 코드/저장소에 커밋하지 않는다. `config.py`는 값을 하드코딩하지 않고 환경에서 로드한다.

## 성공 기준

- 같은 기간·같은 분석의 재실행이 네트워크 조회 없이(캐시 히트) 동작한다.
- 어떤 실행 경로에서도 서버에 임시 테이블이 남지 않는다(정상 종료·예외 종료 모두).
- 보유 기간과 인접한 기간을 요청하면 빠진 날짜 조각만 fetch한다.
- 상태매핑·전이·markov 계산이 로컬 parquet 위에서 서버 없이 재현된다.
- 매니페스트만 읽어도 "무엇이 얼마나 캐시돼 있는지"를 알 수 있다(플랫폼이 소비 가능).
- 수렴 체크로 표본 크기 선택을 근거와 함께 내릴 수 있다.

## 범위 밖 (이 문서에서 다루지 않음)

- 분석 스킬 자체의 로직(서브프로젝트 ②).
- 플랫폼 UI·시각화·대시보드·스킬 카탈로그(서브프로젝트 ③).
- 실시간/최신 신선도 기반 자동 갱신(TTL/freshness). 필요해지면 해당 부분에만 이후에 얹는다.
