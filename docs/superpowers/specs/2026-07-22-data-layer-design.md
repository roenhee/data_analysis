# 데이터 접근·캐시 레이어 설계 (Data Access & Cache Layer)

- 날짜: 2026-07-22
- 상태: 설계 확정 (구현 계획 대기)
- 범위: 정량 분석 플랫폼의 **서브프로젝트 ①** — 공통 데이터 기반 레이어

## 배경

회사 로그 데이터를 Trino(`hadoop-rabbit-trino.onkakao.net`, catalog `hadoop_rabbit_iceberg`, schema `axz_da`)로 조회해 markov 등 정량 분석을 수행한다. 기존 markov 워크플로(`리서치/markov`)의 문제:

- 원본이 약 9.4억 행. 세션 기준 ~100만 행을 샘플링해 서버에 `_rowdata` 테이블을 만들고, 상태매핑·전이·markov 계산을 전부 서버 쿼리(CREATE TABLE 연쇄)로 수행한다.
- 그 결과 (1) 매번 느리고, (2) 서버에 중간 테이블이 계속 쌓이며, (3) 노트북 수동 실행이라 재현이 어렵다.

또한 기존 워크플로 검토(파일 정밀 검토 + 클릭스트림 마르코프 베스트프랙티스 웹 리서치)에서 데이터 기반이 지금 확정해두지 않으면 나중에 되돌리기 어려운 요구사항들이 드러났다(세션 경계, 시퀀스 순서, 샘플링 방식, 검열, action_name 사전 시점, 다중 DB 조인, DB 변동). 본 문서는 이를 모두 반영한다.

이 레이어는 위 문제들을 없애는 공통 기반이다. 분석 스킬(서브프로젝트 ②)과 플랫폼(서브프로젝트 ③)이 모두 이 레이어 위에 올라간다.

## 전체 시스템에서의 위치 (참고)

전체 플랫폼은 3개 서브프로젝트로 분해했고, 본 문서는 ①만 다룬다.

- **① 데이터 접근·캐시 레이어** (본 문서) — 공통 기반.
- **② 분석 스킬들** (Claude Code) — 해석이 필요한 정량 분석. 이 레이어를 import해서 사용.
- **③ 플랫폼** (웹, 혼자 쓰되 읽기전용 웹 공유) — 기록·시각화·대시보드·스킬 프롬프트 카탈로그. 스킬 결과물 파일과 매니페스트를 읽어 표시.

스킬↔플랫폼은 자동 파이프라인이 아니라 **사람이 직접** 오간다: CC에서 스킬을 돌려 결과 파일을 만들고, 플랫폼이 그 파일과 매니페스트를 읽는다.

## 관통 원칙

**"캐시는 원본으로 유연하게, 결정은 버전 관리되는 config로."**
캐시에는 손실 없는 원본에 가까운 데이터를 담고, 분석이 바뀔 수 있는 모든 결정(상태 vocabulary·매핑, 세션 경계, 컷오프, 소스 정의)은 코드나 캐시에 굽지 않고 **버전 관리되는 config 아티팩트**로 둔다. 그래야 결정이 바뀌어도 재-pull 없이 로컬 재계산으로 끝나고, ①이 만든 config를 ②③이 그대로 소비한다.

## 핵심 결정 사항

1. **형태**: 공용 파이썬 패키지 `data_layer/`. 각 분석 스킬이 `import`해서 사용한다. (별도 조회 스킬/CLI 아님 — 호출 단계를 늘리지 않기 위해)
2. **연산 위치 (하이브리드, "서버가 줄이고 로컬이 캐시한다")**: 무거운 집계/축소는 Trino에서 하되 결과는 작게 만들어 로컬로 가져오고, 이후 분석 연산은 로컬 DuckDB에서 수행한다.
3. **서버 잔여물 0**: 서버 임시 테이블은 세션 프리픽스로 만들고, 결과를 pull한 직후 DROP한다. 누락 대비 sweep 정리 기능을 둔다. 서버에 아무것도 영구히 남기지 않는다.
4. **캐시 무효화**: 내용 기반 + 수동 갱신. 캐시 키 = `hash(쿼리문 + 기간/파라미터 + 소스버전 + config버전)`. 같은 요청이면 영구 재사용, `refresh=True`일 때만 재조회.
5. **2층 캐시 + config/차원**:
   - **기반 데이터셋**(원본 이벤트 행)은 **개체 첫이벤트일자(entity-start-day)별 조각**으로 캐시 → 범위 재사용·델타 fetch·보유기간 표시가 나오면서도 세션이 조각 경계로 잘리지 않는다.
   - **파생 집계 결과**는 **내용 해시**로 캐시(날짜로 쪼개 재사용 불가한 비율/집계 대상). 확률뿐 아니라 **카운트도 함께 저장**(신뢰구간·스무딩·최소카운트 계산을 ②가 할 수 있게).
   - **차원(dimension) 소스**(성·연령 등 유저 속성)는 유저 키로 별도 캐시.
   - 상태 vocabulary·매핑, 세션화 파라미터, 컷오프는 캐시에 굽지 않고 **analysis config**로 둔다.
6. **Phase 0 프로파일/사전(dictionary)**: 대량 pull 앞에, 서버에서 `action_name` 카운트만 싸게 훑어 순위·컷오프·상태매핑·`other` 버킷을 담은 **버전 관리 사전 아티팩트**를 만든다. "저장 전에 결정"을 지키되, 이벤트 캐시엔 **원본 `action_name`을 그대로** 저장해 컷/매핑 변경 시 재-pull 없이 로컬 재계산한다. 이 사전은 ②③도 그대로 소비한다.
7. **세션-완결 샘플링 + 재현성**: 샘플링은 **개체 `(app_user_id, isuid)` 통째로**(부분 세션 금지). 시드와 샘플 파라미터(목표 크기, 방식)를 매니페스트에 기록해 재현 가능하게 한다. (기존 markov의 무시드·"100만 vs 150만" 불일치 문제 해소.)
8. **세션 경계 = 다운스트림 config**: 세션을 캐시에 굽지 않는다. 캐시는 개체별 원본 이벤트 + 정렬키만 제공하고, 세션 나누기(비활동 타임아웃 등, 기본 30분)는 재실행 가능한 config 단계로 둔다 → 타임아웃 민감도·시간 동질성 검정을 ②가 할 수 있다.
9. **검열(censoring) 보존**: 추출 윈도우 경계에 걸친 개체(윈도우 시작 전 개시 / 끝 시점 진행중)를 식별할 수 있게 윈도우 경계와 open/closed 플래그를 기록한다.
10. **소스 어댑터 / 확장성**: 접속·테이블·컬럼 매핑을 config로 선언한다. **DB 교체·추가·스키마 드리프트를 코드 수정 없이 config로 흡수**한다. 이벤트 소스 + 차원 소스(성·연령 등)를 같은 방식으로 등록하고, 조인은 로컬 DuckDB에서 수행한다.
11. **표본 크기는 실측으로 결정**: 표본을 키우며 핵심 지표가 안정되는지 확인하는 수렴 체크를 제공한다. "많을수록 정확"의 이득은 √n으로만 커지고 편향은 줄지 않으므로, 양은 철학이 아니라 데이터가 정하게 한다.

## 데이터 흐름 (3단계)

```
Phase 0 · 프로파일        Phase 1 · Fetch (서버 축소→로컬)         Phase 2 · 로컬 연산
─────────────────        ──────────────────────────────         ─────────────────
Trino: action_name       Trino(전수, 개체 완결 샘플링)            DuckDB (로컬 parquet)
카운트만 훑기       →     └ 임시테이블(세션 프리픽스)        →    상태매핑·dedup·세션화
                         ──(결과 pull)──▶ 로컬 조각 저장          ·전이·markov·조인·분석
사전 아티팩트 생성        └ pull 직후 즉시 DROP(finally+sweep)     config/사전을 주입해 수행
(컷·vocab·매핑, 버전)    원본 action_name 유지, 개체-완결
        │                        │                                       │
        └──────────────── analysis config (버전 관리, ①②③ 공유) ───────┘
```

- **Phase 0**: 사전이 없거나 갱신이 필요할 때만. 결과는 config로 저장.
- **Phase 1** 첫 실행: 서버에서 개체-완결 샘플로 축소 → 로컬 조각 저장 → 서버 테이블 DROP.
- **Phase 1** 재실행: 매니페스트 확인 → 이미 있는 조각/결과는 네트워크 0으로 재사용, 빠진 부분만 fetch.
- **Phase 2**: 모든 다운스트림 분석(상태매핑·dedup·세션화·전이·markov·차원 조인 등)은 로컬 parquet 위 DuckDB에서 수행 → 빠르고 오프라인·재현 가능.

## 로컬 캐시 레이아웃

```
cache/
  events/                          # 기반: 원본 이벤트 행. 개체 첫이벤트일자별 조각
    start_day=2026-01-05.parquet   #  → 한 개체(=세션 후보)의 모든 행이 한 조각에
    start_day=2026-01-06.parquet   #  → 델타 fetch/샘플링이 개체를 쪼개지 않음
    ...
  dims/                            # 차원 소스 (유저 속성 등), 유저 키
    demographics.parquet
    ...
  results/                         # 파생 집계 결과 (내용 해시). 카운트+확률
    <hash>.parquet
    ...
  config/                          # 버전 관리 analysis config (사전·매핑·세션화·소스)
    dictionary.v1.json
    sources.json
    ...
  manifest.json                    # 색인: 스킬 + 플랫폼 공용
```

- 요청 기간 = 해당 기간에 **개시된 개체** 조각들의 합집합. 있는 날은 재사용, 빠진 날만 서버에서 가져와 조각 추가.
  - 예: `2026-01-05~02-01` 보유 상태에서 `~02-02` 요청 → **02-02에 개시된 개체만** fetch.
- 파티션 키는 **이벤트 일자가 아니라 개체 첫이벤트일자**다. 세션이 자정을 넘겨도 개체 전체가 한 조각에 있으므로 시퀀스가 조각 경계에서 잘리지 않는다. `day`(이벤트 일자)는 컬럼으로 보존하되 파티션/세션 키로 쓰지 않는다.
- 일자별 델타 재사용은 **행 단위 기반 데이터에만** 적용된다. 비율/집계 같은 파생 결과는 날짜로 분해되지 않으므로 내용 해시 캐시로 다룬다(재계산은 로컬 이벤트 캐시에서 빠르게).

## Analysis config (버전 관리 공유 계약)

캐시에 굽지 않는 모든 결정을 담는 버전 관리 아티팩트. ①이 만들고 ②③이 그대로 소비한다. 바뀌면 config 버전만 올리고 로컬 재계산.

- **dictionary** — `action_name` 순위·컷오프(예: 누적 95%)·상태 매핑 규칙(복합상태 규칙 + 매핑 테이블 + `other` 폴백)·vocabulary. Phase 0 산출물.
- **sessionization** — 세션 분할 규칙(비활동 타임아웃, 기본 30분), START/END 및 종료 사유(정상/타임아웃/전환) 규칙, 연속 중복(self-loop) dedup 정책.
- **sources** — 소스 레지스트리(아래 "소스 어댑터").

## 이벤트 스키마 (기반 캐시 컬럼)

모든 분석의 합집합. `service_code/layer1/layer2`는 상태 파생에 쓰이는 **load-bearing** 컬럼이며 단순 표시가 아니다.

- 식별/조인: `app_user_id`, `isuid`
- 정렬(이중 키, 둘 다 필수): `access_time`(timestamp, 초 해상도), `access_timestamp`(ms epoch, 타이브레이커)
- 시간/필터: `day`
- 행동: `action_type`, `action_name`(원본 유지), `action_kind`
- 상태 파생: `service_code`, `layer1`, `layer2`, `layer3`, `page_meta_id`
- 체류시간(파이프라인이 duration-only 행을 거르기 **전에** 보존): `usage_duration`, `custom_duration`, `custom_duration_timetalk_container`
- 세그먼트: `os`, `app_version` (+ 차원 조인으로 성·연령 등 확장)

집계로 미리 접지 않는다(그레인 = 원본 이벤트 1행). 상태 매핑·dedup·세션화는 Phase 2에서 config를 적용해 수행한다.

## 매니페스트 (`cache/manifest.json`)

캐시 색인. 최소 스키마:

- `events`: 조각별 `{ start_day, entities, rows, size_bytes, source_id, source_query_hash, sample: {method, target, seed}, window_bounds, created_at }`
- `dims`: 소스별 `{ name, source_id, key, rows, created_at }`
- `results`: 항목별 `{ hash, source_summary, date_range, params, config_version, rows, size_bytes, created_at }`
- `config`: `{ dictionary_version, sessionization_version, sources_version }`

`manifest.py`가 읽기/쓰기와 질의 API(보유 기간, 캐시 목록, 사용된 config 버전)를 제공하고, 플랫폼(③)이 이 API를 그대로 사용한다.

## 패키지 구성 `data_layer/`

각 모듈은 하나의 책임만 갖고 잘 정의된 인터페이스로 통신한다.

- `sources.py` — 소스 레지스트리/어댑터. config에서 소스 정의(접속·catalog·schema·table·auth·중첩→평탄 컬럼 매핑)를 읽어 통일된 인터페이스로 노출. DB 교체·추가·스키마 드리프트를 여기서 흡수.
- `connection.py` — 소스별 커넥션(현재 Trino). context manager로 열고 닫는다.
- `profile.py` — Phase 0. `build_dictionary(window, cutoff=0.95) -> dictionary`. 서버에서 `action_name` 카운트만 훑어 사전 아티팩트 생성/버전화.
- `fetch.py` — Phase 1. `get_events(start, end, refresh=False) -> DataFrame`. 매니페스트로 보유 개체-조각 확인 → 빠진 start_day만 서버에서 **개체-완결 샘플**로 조회(시드/파라미터 기록) → 원본 행 조각 저장 + 매니페스트 갱신 → 서버 임시테이블 DROP → 요청 기간을 합쳐 반환. 상태 매핑/세션화는 굽지 않는다.
- `enrich.py` — 차원 조인. `get_dim(name)`로 차원 소스(성·연령 등)를 유저 키로 캐시 → 이벤트와 **로컬 DuckDB 조인**. 무거운 서버 조인 회피.
- `query.py` — `run(sql, params=None, refresh=False, target="local") -> DataFrame`. 기본은 로컬 DuckDB(캐시된 parquet 대상), 결과를 카운트+확률로 해시 캐시. `target="server"`면 무거운 축소를 서버에서 수행 후 결과만 로컬 캐시.
- `manifest.py` — 매니페스트 읽기/쓰기 + 질의 API. 스킬·플랫폼 공용.
- `cleanup.py` — 세션 프리픽스 기준 서버 임시 테이블 일괄 정리(sweep). 정상 경로 즉시 DROP의 안전망.
- `convergence.py` — `check_convergence(analysis_fn, sizes=[1e6, 5e6, 2e7]) -> report`. 표본 크기를 키우며 핵심 지표가 안정되는지 리포트.
- `config.py` — analysis config(사전·세션화·소스) 및 캐시 경로 로드/버전 관리. 접속 정보는 환경에서 로드(아래).

## 소스 어댑터 / 확장성

- 소스는 config(`cache/config/sources.json`)에 선언한다: `{ id, kind: trino|..., host, catalog, schema, table, auth_ref, column_map(중첩→평탄), filters }`.
- **이벤트 소스**와 **차원 소스**(유저 속성)를 같은 스키마로 등록한다.
- DB가 바뀌면(교체/확장) 새 소스 정의를 추가하거나 기존 정의를 수정하는 것으로 끝난다 — 코드 수정 없음. `sources.py`가 어댑터로 흡수하고, 캐시 키에 소스 버전이 포함돼 캐시 무효화가 정확히 일어난다.
- 조인(예: 이벤트 × demographics)은 서버가 아니라 로컬 DuckDB에서 수행해 대형 서버 조인을 피한다.

## 인증정보 처리

기존 `리서치/markov/env.py`는 TIARA ID/PW를 평문으로 담고 있다. 이 레이어에서는:

- 접속 정보를 환경변수(또는 gitignore된 로컬 설정 파일)에서 읽는다.
- 자격 증명을 코드/저장소/`sources.json`에 커밋하지 않는다. 소스 정의는 `auth_ref`(환경변수 키 이름)만 담고 값은 환경에서 로드한다.

## 성공 기준

- 같은 기간·같은 분석의 재실행이 네트워크 조회 없이(캐시 히트) 동작한다.
- 어떤 실행 경로에서도 서버에 임시 테이블이 남지 않는다(정상 종료·예외 종료 모두).
- 보유 기간과 인접한 기간을 요청하면 그 기간에 개시된 개체 조각만 fetch한다.
- 자정을 넘는 세션이 조각 경계에서 잘리지 않고, 샘플링이 개체를 부분적으로 자르지 않는다.
- 시드·샘플 파라미터가 기록되어 동일 샘플을 재현할 수 있다.
- 사전(컷·vocabulary)·상태 매핑·세션 타임아웃을 바꿔도 **재-pull 없이** 로컬 재계산으로 반영된다.
- 성·연령 등 차원 소스를 로컬 조인으로 이벤트에 붙일 수 있다.
- DB 교체/추가가 config 편집만으로 되고, 캐시가 소스 버전에 따라 정확히 무효화된다.
- 상태매핑·전이·markov 계산이 로컬 parquet 위에서 서버 없이 재현된다.
- 파생 결과에 카운트가 함께 저장돼 ②가 신뢰구간·스무딩·최소카운트를 계산할 수 있다.
- 매니페스트만 읽어도 "무엇이 얼마나(어느 config 버전으로) 캐시돼 있는지"를 알 수 있다(플랫폼이 소비 가능).
- 검열 개체(윈도우 경계 걸침)를 식별할 수 있다.
- 수렴 체크로 표본 크기 선택을 근거와 함께 내릴 수 있다.

## 범위 밖 (이 문서에서 다루지 않음)

- 분석 스킬 자체의 로직(서브프로젝트 ②): 신뢰구간·마르코프 차수 검정·시간 동질성 검정·스무딩·상태 granularity 계층·semi-Markov/HMM/고차 등. 단, ①은 이들이 나중에 가능하도록 원본 이벤트·타임스탬프·세션 그룹·카운트·세그먼트를 보존한다.
- 플랫폼 UI·시각화·대시보드·스킬 카탈로그(서브프로젝트 ③).
- 실시간/최신 신선도 기반 자동 갱신(TTL/freshness). 필요해지면 해당 부분에만 이후에 얹는다.
